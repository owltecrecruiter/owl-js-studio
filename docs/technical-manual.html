5. STEP 判定と CLEAR 保持

判定の本体は evaluateStepProgress / areAllStepsComplete です。学習完了の保持は別関数です。

STEP判定
1ふりがな ON（実行不要）
2gameTitle が初期値から変化し、現在コードの実行成功
3色が初期値から変化し、実行成功
4問題文3つと選択肢9つがすべて初期値から変化し、実行成功
5いずれか1問の correctIndex が初期値から変化し、実行成功し、その問で新しい正解を選んで「正解！」
  • STEP 5 は3問すべての正解番号変更を要求しない（hasChangedCorrectIndex）。
  • 一度 1〜5 が揃うと learningComplete はセッション中保持する（rememberLearningComplete）。
  • その後のタイトル・色・問題の再編集では完了フラグを消さない。
  • 構文／検証エラー中は CLEAR を無効化する。修正後は STEP やり直し不要。
  • 発行は editorMatchesLastRun かつ lastRunWork があるときだけ。未実行の最新コードや古い実行結果は出さない。
  • getLastValidQuizData() は last-run とエディタが一致するときだけデータを返す。bridge クライアントはこの関数を使う。

CLEAR の見た目と発行可否は evaluateCourseClearGate が分けて返します。clearEnabled と canOpenIssuance は別です。

6. パーサ制約

  • 許可された const と、各問の if (selectedIndexN === 0|1|2) だけ。
  • 3問・各3択固定。question4 や余分な文はエラー。
  • 色は rgb(整数, 整数, 整数)。発行 HTML では HEX または名前つき許可色。
  • 学習 JS を実行しない。プレビューはパース結果の work データで動く。

7. 発行フロー

  1. 面接官 GAS が氏名・メールを登録し、8文字コードを生成。スプレッドシートには hash のみ。
  2. 学習者が CLEAR からコードを送る。Pages は検証済み quizData だけを bridge に渡す。
  3. 学習者 GAS がワンタイム消費、Drive 保存、メール添付を行う。
  4. Drive 名：応募者氏名_作品タイトル.html
  5. メール添付名：作品タイトル.html（氏名は付けない）
  6. 件名：【OWL JS Studio】完成したクイズをお届けします
コード平文は生成時だけ画面に出ます。再表示 API はありません。Drive 保存成功後にメールだけ失敗した場合は、コードは使用済みのままファイルが残るので、再発行ではなく管理者の再送を使います。

8. GAS 2プロジェクト

学習者プロジェクト

  • コピー：gas/IssuanceBackend.js、gas/embedded-brand-assets.js
  • 必須プロパティ：SPREADSHEET_ID、CODE_HASH_PEPPER、LEARNER_PAGE_ORIGIN（https://owltecrecruiter.github.io）、PUBLIC_LEARNER_DEPLOYMENT=true、OUTPUT_FOLDER_ID
  • アクセス：Anyone。doPost は無効。管理者関数は public モードで拒否。
  • エディタのファイル保存だけでは公開 Web アプリは更新されない。必ず再デプロイする。

面接官プロジェクト

  • コピー：上記に加え gas/admin/AdminIssuanceApp.js、gas/admin/print-assets.js
  • ADMIN_WEB_APP=true、PUBLIC_LEARNER_DEPLOYMENT は未設定または false
  • 学習者側と同じ SPREADSHEET_ID と CODE_HASH_PEPPER
  • INTERVIEWER_ADMIN_PASSWORD と ADMIN_API_TOKEN は Pages に出さない
  • 手順の詳細は gas/admin/README.md
学習画面の STEP / CLEAR だけを変える改修では、学習者 GAS の再デプロイは不要です。発行 HTML の見た目・検証・Drive 名・メール文面を変えるときだけ両方の GAS を更新します。

9. デプロイ

GitHub Pages

  1. docs/ を更新する。
  2. platform/ の同名4ファイルを揃える。
  3. フッタと studio-core.js 先頭のバージョンを上げる。
  4. main に push する。Pages ソースは docs/。

学習者 GAS を触るとき

  1. Apps Script エディタへソースを貼る。
  2. 新しいデプロイ、または既存デプロイの「デプロイを編集」でバージョンを上げる。
  3. /exec URL が変わったら docs/studio-config.js を更新して Pages も出す。
  4. 必要なら docs/gas-bridge-connectivity-test.html で ping だけ確認する。本番コードは送らない。

10. テスト

ローカル（Node）の例：

node platform/studio-v0920-tests.js
node gas/IssuanceBackend.local-tests.js
node gas/admin/AdminIssuance.local-tests.js

フロントの版ごとのテストは platform/studio-v09*.js です。gitignore のため GitHub には上がりません。判定や CLEAR を変えたら、対応する版のテストと studio-v0920-tests.js 相当を更新します。

ローカルテストは Drive / Mail / LockService をモックします。本番の権限・クォータ・iframe origin はデプロイ後のブラウザでしか確認できません。

11. 改修時の約束

  • vanilla HTML/CSS/JS。学習コードに eval / new Function を使わない。
  • 3問3択ロックを外さない。
  • シークレットを docs/ に書かない。
  • 特典コードのワンタイム性、Drive 保存、メール送信の契約を黙って変えない。
  • STEP 1〜3 を変える必要がない改修では触らない。
  • 公開後の学習完了保持と「未実行コードを発行しない」を壊さない。

運用者向けの当日手順は 運用マニュアル。GAS のプロパティ一覧・bridge の origin 規則・スプレッドシート列は gas/README.md が正本です。
